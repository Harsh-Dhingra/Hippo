# What we measured, and what we did not

**Status:** P2-EVAL-2. Numbers from the commit this file ships in. Reproduce
them with `python -m evals.report`.

Everything below is a number this repository produces on demand. Where a number
is bad, it is here anyway, because a benchmark post that only contains wins is
marketing with a table in it.

---

## The headline, with its caveat first

The caveat is the important part, so it goes first: **the corpus these numbers
come from is one we wrote ourselves.** A self-authored benchmark is the weakest
kind of evidence there is. It cannot tell you Hippo is better than anything; at
best it tells you whether a change we made helped or hurt, measured the same way
twice. Treat every number here as a regression baseline, not a claim.

It is generated by `evals/seed.py`: 432 chunks across 24 channels, 72 planted
facts, 87 labelled questions, deterministic (fingerprint `bb4b7ee414dfe915`), so
two runs differ only if the system did.

```
k=3   recall=0.483 mrr=0.359   lexical=1.00 semantic=0.12 traversal=0.00  leaks=0
k=5   recall=0.506 mrr=0.365   lexical=1.00 semantic=0.21 traversal=0.00  leaks=0
k=10  recall=0.540 mrr=0.371   lexical=1.00 semantic=0.33 traversal=0.00  leaks=0
k=20  recall=0.747 mrr=0.392   lexical=1.00 semantic=0.33 traversal=0.75  leaks=0
```

## The losses

### Semantic recall is 0.33 and that is bad

A third. Two thirds of the questions phrased in different words from the
content they are about do not retrieve it in the top twenty.

The reason is not subtle: the default embedder is `HashingEmbeddings`, which is
lexical. It hashes tokens into a vector. It has no idea that "brought to a
standstill" and "blocked" are the same thing, and the semantic cases are
specifically the ones written to require knowing that.

This is a deliberate default, not an oversight — it needs no service, no key
and no network, so the project runs before anyone has chosen a model. But it
means the shipped default is a keyword system wearing a vector index, and the
number says so.

`python -m evals.embeddings` compares real models on this same corpus.
`mxbai-embed-large` won on overall recall and is the configured default for the
`openai` provider, which speaks to Ollama, vLLM and LM Studio as well as to
OpenAI. That measurement was taken on a laptop; the recall numbers transfer, the
latency numbers do not, and STACK.md says so.

### Graph traversal contributes nothing below k=20

`graph=0.000` at k=3, 5 and 10, then 0.250 at k=20. Traversal recall goes
0.00 → 0.75 in the same step.

Neighbours found by walking the graph are ranked below direct hits by
construction, so at small k they are all crowded out. That is arguably correct —
a direct match should beat a neighbour — but it means the graph half of "hybrid
retrieval" earns its place only at generous k, and any deployment using a
smaller context budget is running a two-way hybrid, not a three-way one.

Migration 014 improved this by carrying a seed's rank through the walk, so a
neighbour inherits the standing of what it was found from. Before that,
traversal recall was 0.00 at every k measured. It is better and it is not good.

### Six traversal cases still miss entirely

`traversal-8`, `-26`, `-29`, `-35`, `-41`, `-50` — all the same shape: "resolved
by rolling forward the migration on node N". The fact is one hop from the
question's subject, and the hop is not made. Named individually because a
percentage hides which six.

### Keyword recall of 1.00 is less impressive than it looks

`lexical=1.00` at every k. Every exact-identifier question retrieves its target.
That is the case Postgres FTS is best at and it would be alarming if it failed;
it is a floor, not an achievement.

Worth recording that it was 0.00 until we measured it. `plainto_tsquery` ANDs
its lexemes, so a multi-word question matched only documents containing every
word, and keyword search was contributing almost nothing. Migration 008 relaxed
the conjunction to a disjunction. The eval harness found that; reading the code
had not.

### The curation pass does not improve retrieval

P2-MEM-2 demotes noise — acknowledgements, boilerplate, duplicates. Run as a
controlled pair over identical rows, the effect on recall@20 is **0.0000** at
every k.

It looked like +0.033 before it was controlled. That difference was the HNSW
index, which is approximate and reorders slightly when the table is rewritten.
Curation works where noise actually competes, which is browse rather than
search: top-20 noise goes 5 → 0, and top-50 goes 16 → 2.

### Recall is approximate

`chunks_embedding_idx` is HNSW. It trades exactness for speed and its graph
depends on insertion order, so a table rewrite can move recall a point or two
with nothing in retrieval having changed. Two numbers are comparable only if
they came from the same table state. The floors carry margin for this.

## The number that is not a metric

```
leaks          0     (87 golden cases)
leaks          0     (75 red-team probes)
```

Leaks are a bug list, not a rate. One is a release blocker.

Backing them, `tests/test_permission_property.py` generates **10,000 random
permission worlds** and evaluates each against a Python model of the
specification written from the spec rather than from the SQL, plus a Hypothesis
suite that shrinks counterexamples. `tests/test_roles.py` asserts the entire
grant matrix and fails on any table it does not mention, including column-level
grants that `has_table_privilege` cannot see.

And an honest note about an earlier version of this number. When a better
embedder was tried, the leak count moved — not because of a permission bug, but
because six paraphrases were reused across 24 channels and the harness matched
needles on a 48-character prefix that truncated the channel name. A better
retriever found the twin from another channel and the harness called it a leak.
The earlier `leaks=0` was partly luck. The needles are distinct now.

## Published benchmarks: what we ran, and what we did not

**We have not run Enterprise-Bench or any other published enterprise-agent
benchmark.** Not "we ran it and did poorly" — we did not run it. PROJECT.md
conditions this fragment on "if reproducible", and we have not verified a
reproducible public artifact to run against. Claiming a result here would be
worse than having none.

What exists instead is `evals/external.py`, which loads a benchmark in a
documented JSON format and runs it through the ordinary retrieval path — no
side door, so it measures the system that actually ships:

```
python -m evals.external path/to/benchmark.json
```

### Why most published benchmarks cannot test the thing that matters

This is the substantive point, not an excuse.

Published RAG and enterprise-agent benchmarks supply documents and questions and
score the answer. Hippo's central claim is not that it answers well. It is that
it answers **only from what the person asking is allowed to read**. A corpus
where every document is readable by everyone cannot test that, because there is
no wrong document to return.

So `evals/external.py` refuses to report `leaks: 0` for a benchmark with no
permission model. It prints:

```
leaks          not measured — this benchmark has no permission model,
               so it cannot test the claim that matters here
```

Zero out of zero possible leaks is not a result, and printing it as one would be
the exact dishonesty this document exists to avoid.

### What a benchmark would need to be useful here

1. **Per-document audiences**, and people who differ in what they may read.
2. **Questions asked by more than one person**, where the correct answer differs
   by asker — including cases where the correct answer is "I don't have anything
   on that".
3. **Group membership**, since real ACLs are mostly groups, and group expansion
   is where permission bugs live.
4. **Revocation over time**, because a permission system is easy to get right at
   rest and hard to get right while changing.

The format `evals/external.py` reads has all four. If a published benchmark with
these properties exists and we have missed it, please open an issue — we will
run it and publish the result whichever way it comes out.

## Prompt injection

`tests/fixtures/injection/corpus.json` holds 16 attack shapes across five
families: instruction override, exfiltration, unsolicited action, integrity, and
obfuscation. Every one is driven through a model that fully complies with it,
because a guard that holds only because the model behaved is not a guard.

**Nothing in the codebase recognises any of them.** There is no phrase list, and
a test asserts no distinctive string from the corpus appears in the source. What
stops each attack is structural — the decision to act is read from the user's
question, the action vocabulary is closed, targets are named by source marker.
See `docs/THREAT-MODEL.md` §4.2.

Two corpus entries are marked `defeated_by: nothing`, and that is the honest
answer. If someone writes a lie into Slack, Hippo will repeat it, cited. This
system prevents content from being *acted* on and makes what an answer was built
from *visible*. It does not adjudicate whether your Slack messages are true.

## Reproducing all of this

```
python -m evals.report                  # the table at the top, plus red team
python -m evals.embeddings              # compare embedding models on this corpus
python -m evals.external bench.json     # somebody else's benchmark
pytest tests/test_permission_property.py   # 10,000 permission worlds
```

The first three build their own scratch database and tell you its name so you
can drop it.
